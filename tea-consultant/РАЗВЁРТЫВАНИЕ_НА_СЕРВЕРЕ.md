# Чайный город — развёртывание на сервере / виртуалке

Инструкция для чистой Linux-виртуалки (Ubuntu 24.04/Debian — актуальный вариант, дата-центр в ЕС). Если сервер другой — шаги те же по сути, отличаются только команды установки пакетов.

**Почему сервер должен быть в ЕС/вне России**: у OpenAI API нет России в списке поддерживаемых стран — запросы с российского IP могут блокироваться или приводить к бану ключа/аккаунта. Поэтому под этот проект — отдельная виртуалка в Евросоюзе, никак не связанная с уже существующими российскими серверами/CMS.

Все упомянутые файлы конфигов лежат в папке `deploy/`:

```
deploy/nginx.conf.example         ← конфиг Nginx (рекомендуется)
deploy/apache-vhost.conf.example  ← конфиг Apache (альтернатива)
deploy/php-production.ini.example ← продовые настройки PHP
deploy/logrotate-tea-consultant.example ← ротация логов приложения
deploy/cleanup.sh                 ← периодическая чистка старых служебных файлов
deploy/deploy.sh                  ← разворачивание/обновление кода на сервере
```

## Шаг 1. Минимальные требования к серверу

- Linux (Ubuntu 24.04 или Debian — ниже команды под них; на Ubuntu 24.04 в базовой поставке идёт PHP 8.3)
- PHP 8.2 или новее, с расширениями: `curl`, `mbstring`, `json` (обычно идут в базовой поставке)
- Nginx **или** Apache — выбрать один вариант
- Поддомен/домен, направленный на IP сервера (A-запись) — нужен для HTTPS. DNS раскатывается не мгновенно, стоит прописать запись заранее, пока идут остальные шаги
- Открытые порты 22 (SSH), 80 и 443 в firewall

Внешняя база данных, Redis, очереди и т.п. — **не нужны**. Всё хранится в файлах на диске.

## Шаг 2. Установка пакетов

Пакет `php-fpm` (без указания версии в названии) сам подтянет актуальную для вашего релиза версию PHP — не нужно гадать, 8.2 это или 8.3.

Вариант с Nginx + PHP-FPM (рекомендуется, лучше держит нагрузку под MVP-тесты):

```bash
sudo apt update
sudo apt install -y nginx php-fpm php-curl php-mbstring unzip rsync ufw certbot python3-certbot-nginx
```

Вариант с Apache + mod_php (проще для очень маленькой виртуалки):

```bash
sudo apt update
sudo apt install -y apache2 libapache2-mod-php php-curl php-mbstring unzip rsync ufw certbot python3-certbot-apache
sudo a2enmod rewrite headers
```

Проверить версию и сокет:

```bash
php -v                 # должна быть 8.2+
ls /run/php/           # запомните точное имя сокета, например php8.3-fpm.sock — понадобится в конфиге nginx
```

### Firewall

Сразу после установки пакетов, пока не забыли — иначе после `ufw enable` можно потерять SSH-доступ:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'   # или 'Apache Full', если выбрали Apache
sudo ufw enable
sudo ufw status
```

## Шаг 3. Залить код на сервер

Проще всего — скопировать распакованный архив проекта на сервер (`scp`, `rsync` или через git, если код уже в репозитории разработчика) в любую временную папку, например `~/tea-consultant-src`, а дальше использовать готовый скрипт:

```bash
cd ~/tea-consultant-src
sudo ./deploy/deploy.sh /var/www/tea-consultant
```

Скрипт `deploy.sh`:
- копирует код в `/var/www/tea-consultant`, не трогая `.env`, накопленную историю (`storage/`) и логи (`logs/`) при повторных запусках (то есть его же можно использовать и для последующих обновлений — просто зальёте новую версию кода в `~/tea-consultant-src` и запустите ещё раз);
- при первом запуске создаёт `.env` из `.env.example` и явно напоминает вписать в него ключ OpenAI;
- выставляет владельца файлов на пользователя веб-сервера (`www-data` по умолчанию — если у вас PHP-FPM работает от другого пользователя, запустите `sudo WEB_USER=имя_пользователя ./deploy/deploy.sh /var/www/tea-consultant`);
- проверяет синтаксис всех `.php`-файлов, чтобы не выкатить битый код.

## Шаг 4. Заполнить .env

```bash
sudo nano /var/www/tea-consultant/.env
```

Обязательно: `OPENAI_API_KEY`. Остальное можно оставить по умолчанию на старте (описание всех полей — в `README.md` и в `ДЛЯ_РАЗРАБОТЧИКА.md`).

**Ключ вписывается только через редактор прямо на сервере** — не передавайте его через чаты/тикеты.

## Шаг 5. Настроить веб-сервер

### Если Nginx

```bash
sudo cp /var/www/tea-consultant/deploy/nginx.conf.example /etc/nginx/sites-available/tea-consultant.conf
sudo nano /etc/nginx/sites-available/tea-consultant.conf   # подставить домен и путь к php-fpm.sock
sudo ln -s /etc/nginx/sites-available/tea-consultant.conf /etc/nginx/sites-enabled/
sudo nginx -t                      # проверка конфига
sudo systemctl reload nginx
```

Путь к сокету PHP-FPM — тот же, что вы уже смотрели в Шаге 2 командой `ls /run/php/` (на Ubuntu 24.04 обычно `php8.3-fpm.sock`; в `deploy/nginx.conf.example` по умолчанию подставлен именно он — проверьте, что совпадает с вашим).

### Если Apache

```bash
sudo cp /var/www/tea-consultant/deploy/apache-vhost.conf.example /etc/apache2/sites-available/tea-consultant.conf
sudo nano /etc/apache2/sites-available/tea-consultant.conf   # подставить домен и путь
sudo a2ensite tea-consultant.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
```

На этом этапе стоит открыть `http://<IP-сервера-или-домен>/` в браузере — уже должна открыться веб-морда чата (сам чат работать не будет без HTTPS+ключа, но статика должна отдаваться).

### Пароль для смотрелки диалогов (/admin/)

В `deploy/nginx.conf.example` (и `apache-vhost.conf.example`) уже прописана защита страницы `/admin/` паролем (HTTP Basic Auth) — без этого шага она будет **недоступна с ошибкой 500/403**, пока не создан файл пароля:

```bash
sudo apt install -y apache2-utils   # пакет с htpasswd, для nginx и apache он один и тот же
sudo htpasswd -c /etc/nginx/.htpasswd-tea-admin admin   # для Apache: /etc/apache2/.htpasswd-tea-admin
# попросит придумать и повторить пароль — это и есть логин/пароль от смотрелки
sudo systemctl reload nginx   # или apache2
```

Открывается на `https://ваш-домен/admin/` — покажет список диалогов (последние сверху), с поиском по тексту и фильтром "только с ошибками"; клик по диалогу — вся переписка целиком в виде тех же пузырьков, что и на сайте, плюс модель/токены/время ответа.

Если позже нужно добавить второго человека с доступом — та же команда `htpasswd`, но без `-c` (он затирает файл целиком):
```bash
sudo htpasswd /etc/nginx/.htpasswd-tea-admin имя_второго_пользователя
```

## Шаг 6. HTTPS (обязательно перед реальным использованием)

Пакеты `certbot` и `python3-certbot-nginx`/`python3-certbot-apache` уже поставлены на Шаге 2, так что достаточно:

```bash
sudo certbot --nginx -d tea.example.com             # для Apache: --apache вместо --nginx
```

Certbot сам допишет редирект с 80 на 443 и настроит автопродление сертификата (проверить: `sudo certbot renew --dry-run`).

Без HTTPS браузеры всё активнее блокируют cookie (а cookie `tea_cid` — единственный способ приложения помнить разговор), так что это не опциональный шаг.

## Шаг 7. Продовые настройки PHP

Подставьте свою версию PHP вместо `8.3` (проверить: `php -v`; `deploy.sh` при разворачивании тоже пытается определить сокет/сервис автоматически и подсказывает точное имя в конце вывода):

```bash
# для php-fpm:
sudo cp /var/www/tea-consultant/deploy/php-production.ini.example /etc/php/8.3/fpm/conf.d/99-tea-consultant.ini
sudo systemctl restart php8.3-fpm

# для mod_php (Apache):
sudo cp /var/www/tea-consultant/deploy/php-production.ini.example /etc/php/8.3/apache2/conf.d/99-tea-consultant.ini
sudo systemctl restart apache2
```

Главное в этом файле: `display_errors = Off` — иначе любая ошибка PHP попадёт прямо в тело JSON-ответа и сломает чат на фронтенде (мы уже ловили ровно этот баг на dev-окружении, см. `ДЛЯ_РАЗРАБОТЧИКА.md`, раздел 6).

## Шаг 8. Ротация логов и чистка старых файлов

```bash
sudo cp /var/www/tea-consultant/deploy/logrotate-tea-consultant.example /etc/logrotate.d/tea-consultant
sudo nano /etc/logrotate.d/tea-consultant   # подставить реальный путь, если отличается от /var/www/tea-consultant

sudo crontab -e
# добавить строку:
# 15 4 * * * /var/www/tea-consultant/deploy/cleanup.sh /var/www/tea-consultant >> /var/log/tea-consultant-cleanup.log 2>&1
```

`logs/requests.log` без ротации будет расти бесконечно. `cleanup.sh` подчищает старые служебные файлы rate-limit (живут максимум несколько минут по смыслу) и старую историю диалогов (по умолчанию — старше 90 дней, срок можно поменять внутри скрипта).

## Шаг 9. Проверка

```bash
curl -i https://tea.example.com/
curl -s -X POST https://tea.example.com/api/chat.php \
  -H "Content-Type: application/json" \
  -d '{"conversation_id":null,"message":"Посоветуй лёгкий чай на вечер"}'
```

Второй запрос должен вернуть JSON вида `{"success":true,"conversation_id":"c_...","answer":"...","product_ids":[...],"follow_up_question":null}`. Если вместо этого пришла ошибка 500 — смотреть `logs/requests.log` на сервере и `error_log` из php-production.ini (путь `/var/log/php-tea-consultant-error.log`).

Дальше — открыть сайт в браузере и пройтись по тестовым сценариям из исходного ТЗ.

## Обновление в будущем

Залить новую версию кода в любую временную папку на сервере и снова выполнить `sudo ./deploy/deploy.sh /var/www/tea-consultant` — `.env`, история диалогов и логи не тронутся, перезатрётся только код.

## Если что-то не открывается — куда смотреть

1. `sudo nginx -t` / `sudo apache2ctl configtest` — синтаксис конфига веб-сервера.
2. `sudo systemctl status php8.3-fpm` (подставьте свою версию; или `apache2`) — жив ли процесс.
3. `sudo tail -f /var/log/nginx/tea-consultant-error.log` (или apache-аналог) — ошибки на уровне веб-сервера.
4. `tail -f /var/www/tea-consultant/logs/requests.log` — лог самого приложения (JSON построчно, там же видно ошибки обращения к OpenAI).
5. `tail -f /var/log/php-tea-consultant-error.log` — PHP-ошибки уровня кода (если `display_errors=Off`, как и должно быть на проде, все ошибки идут только сюда, не в браузер).
