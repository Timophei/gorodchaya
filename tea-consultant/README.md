# Чайный город — прототип ИИ-консультанта

Простой прототип: веб-чат с ИИ-консультантом, который подбирает чай из каталога
и возвращает текст ответа + ID рекомендованных товаров. Без базы данных,
без карточек товаров — только текст и список ID (по упрощённому ТЗ).

## Структура проекта

```
tea-consultant/
├── public/                  ← это DocumentRoot для Apache (веб-корень)
│   ├── index.html            веб-морда чата
│   ├── css/style.css
│   ├── js/chat.js             cookie с conversation_id, рендер чата, запросы к API
│   └── api/
│       └── chat.php           ЕДИНАЯ точка входа: приёмник + ответчик
├── src/                      backend-классы (вне веб-корня, недоступны напрямую)
│   ├── Config.php             загрузка .env
│   ├── Catalog.php            каталог чаёв + проверка ID
│   ├── PromptLoader.php       загрузка инструкции консультанта
│   ├── HistoryStore.php       файловая история диалогов
│   ├── RateLimiter.php        ограничение частоты запросов
│   ├── Logger.php             журналирование в JSON Lines
│   └── OpenAiClient.php       обращение к OpenAI Responses API
├── data/teas.json            каталог чаёв (редактируется без изменения кода)
├── prompts/tea-master.txt    инструкция консультанта (редактируется без изменения кода)
├── storage/
│   ├── conversations/         история диалогов (по файлу на conversation_id)
│   └── ratelimit/              состояние rate limiter
├── logs/requests.log         журнал запросов (JSON Lines, по одной записи в строке)
├── tests/smoke_test.php      офлайн-проверка логики (без обращения к OpenAI)
├── .env.example               шаблон конфигурации
└── .gitignore
```

## Как это разбито на этапы (как вы просили)

1. **Веб-морда** (`public/index.html`, `css/style.css`, `js/chat.js`) —
   чат, история диалога на экране кэшируется в `sessionStorage` (чтобы не
   пропадала при обновлении страницы), а `conversation_id`, который связывает
   браузер с историей на сервере, хранится в **cookie** `tea_cid` (30 дней).
   Кнопка «Новый разговор» стирает cookie и локальный кэш.
2. **Бекенд-приёмник** (начало `public/api/chat.php`) — принимает POST-запрos,
   проверяет длину сообщения, валидирует/генерирует `conversation_id`,
   применяет rate limit, подгружает историю диалога и каталог.
3. **Бекенд-ответчик** (вторая половина `public/api/chat.php` +
   `src/OpenAiClient.php`) — собирает запрос к OpenAI Responses API
   (инструкция + каталог в начале, история + новое сообщение в конце — для
   Prompt Caching), получает Structured Output, проверяет `product_ids` по
   каталогу, сохраняет историю, пишет журнал, возвращает фронтенду только
   безопасный текстовый ответ.

## Почему история «по cookie», а не полностью в cookie

Cookie ограничены по размеру (~4 КБ) и их легко подделать на клиенте. Поэтому
в cookie хранится только `conversation_id` — «пропуск», по которому сервер
находит файл с историей в `storage/conversations/`. Так надёжнее и ближе к
тому, как это будет работать при переходе на MySQL. Если вам принципиально
важно держать историю целиком в браузере (а не на сервере) — скажите, это
легко переключить.

## Установка на сервер

1. Скопируйте проект на сервер, например в `/var/www/tea-consultant`.
2. Настройте Apache так, чтобы **DocumentRoot указывал на папку `public/`**:

   ```apache
   <VirtualHost *:80>
       ServerName tea.example.com
       DocumentRoot /var/www/tea-consultant/public

       <Directory /var/www/tea-consultant/public>
           AllowOverride All
           Require all granted
       </Directory>
   </VirtualHost>
   ```

   Благодаря этому `data/`, `prompts/`, `src/`, `storage/`, `logs/` физически
   находятся вне веб-корня и не отдаются по HTTP. Дополнительно в каждой из
   этих папок лежит `.htaccess` с `Require all denied` — на случай, если
   DocumentRoot когда-нибудь укажут на корень проекта по ошибке.

3. Скопируйте `.env.example` в `.env` и заполните:

   ```bash
   cp .env.example .env
   ```

   Обязательно укажите `OPENAI_API_KEY` (отдельный Service Account проекта
   TeaGorod) и при необходимости `OPENAI_PROJECT_ID`.

4. Дайте веб-серверу права на запись в `storage/` и `logs/`:

   ```bash
   chown -R www-data:www-data storage logs
   chmod -R 770 storage logs
   ```

5. Проверьте PHP-модули: нужен `curl` (обычно включён по умолчанию).

6. Откройте `https://ваш-домен/` — должна открыться страница чата.

## Локальная проверка без Apache

```bash
php -S 127.0.0.1:8091 -t public
```

Откройте `http://127.0.0.1:8091/`.

## Офлайн-тест логики (без обращения к OpenAI)

```bash
php tests/smoke_test.php
```

Проверяет каталог, историю, rate limiter, логгер и конфиг напрямую, без
сетевых вызовов — быстрый способ убедиться, что ничего не сломалось после
правок кода.

## О модели `gpt-5.6-terra` / `gpt-5.6-luna`

Название модели вынесено в `.env` (`OPENAI_MODEL`) — переключение между Terra
и Luna не требует правки кода, просто смените значение и перезапустите
запросы. **Важно:** на момент подготовки этого прототипа у меня нет доступа к
актуальной документации OpenAI по этим конкретным моделям (они, судя по
всему, новее моего среза знаний), поэтому:

- код обращения к Responses API (`src/OpenAiClient.php`) написан по общей
  структуре Responses API + Structured Outputs (`instructions` + `input` +
  `text.format.json_schema`), актуальной на момент написания;
- перед первым реальным запуском стоит свериться с официальной документацией
  OpenAI для `gpt-5.6-terra`/`gpt-5.6-luna` — не изменились ли имена полей
  запроса/ответа, доступна ли модель вашему ключу/проекту;
- если что-то в API отличается — правки локализованы в одном файле
  (`OpenAiClient.php`), остальной код (каталог, история, фронтенд, логи) их
  не касается.

## Редактирование без изменения кода

- **Каталог чаёв** — `data/teas.json`. Добавляйте/убирайте товары, меняйте
  описания — код трогать не нужно.
- **Инструкция консультанта** — `prompts/tea-master.txt`. Обычный текстовый
  файл, редактируется как угодно.
- **Модель, таймауты, лимиты** — `.env`.

## Безопасность

- `OPENAI_API_KEY` читается только на сервере (`src/Config.php`), никогда не
  попадает в ответ фронтенду и не пишется в лог.
- `.env` исключён из Git (`.gitignore`).
- Длина сообщения пользователя ограничена (`MAX_MESSAGE_LENGTH`, по умолчанию
  1000 символов).
- Rate limit по IP: по умолчанию 20 запросов / 5 минут (`RATE_LIMIT_*`
  в `.env`).
- Таймаут обращения к OpenAI: по умолчанию 30 сек (`OPENAI_TIMEOUT_SECONDS`).
- При ошибке или недоступности OpenAI пользователь видит нейтральное
  сообщение, а технические детали (включая сырой ответ OpenAI) уходят только
  в `logs/requests.log`.
- ID товаров, которых нет в `data/teas.json`, никогда не показываются
  пользователю и логируются как ошибка (`invalid_product_ids`).

## Формат журнала (`logs/requests.log`)

По одной JSON-записи на строку (JSON Lines) — удобно выгружать и разбирать,
например, через `jq` или загрузку в pandas/Excel построчно:

```json
{"timestamp":"...","conversation_id":"c_...","question":"...","answer":"...","product_ids":[101],"invalid_product_ids":[],"model":"gpt-5.6-terra","input_tokens":0,"cached_input_tokens":0,"output_tokens":0,"duration_ms":0}
```
