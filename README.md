# Чайный город

Интернет-магазин чая с консультантом-мастером (gorodchaya.ru, gorodchaya.online) и лендинг CRM.Капитан (btxcap.ru, btxcap.online). Всё живёт на одном сервере Ubuntu 24.04: nginx, PHP-FPM, Node.js, без Docker.

## Что где

| Папка | Что это | На сервере |
|---|---|---|
| `site/` | Витрина: страницы, стили, `assets/common.js` (корзина, шапка, метка посетителя) | `/var/www/chainy-gorod-site` |
| `backend/` | API магазина (Node/Express, хранение в JSON): каталог, заказы, вход через Telegram, посетители | `/var/www/chainy-gorod-backend`, сервис `chainy-gorod-backend`, порт 4000 |
| `generator/` | Печёт `tea-<id>.html` и `sitemap.xml` из каталога (раз в час по cron) | `/opt/chainy-gorod-generator` |
| `tea-consultant/` | Чат с мастером (PHP + OpenAI) и админка `/admin/` (диалоги, заказы, пользователи, продукты) | `/var/www/tea-consultant` |
| `btxcap/` | Лендинг CRM.Капитан с формой заявки в Битрикс24 | `/var/www/btxcap` |

## Установка с нуля

```
bash install.sh              # пакеты, сайты, сервисы, nginx, файрвол, ежедневный бэкап
bash ssl.sh почта@пример.ru  # сертификаты, когда DNS доменов указывает на сервер
```

`install.sh` повторно запускать безопасно, но он перезаписывает конфиги nginx: после него снова запустите `ssl.sh`.

## Обновление работающего сервера (через GitHub)

На сервере, один раз:

```
git clone https://github.com/Timophei/gorodchaya /opt/gorodchaya
```

Дальше после каждого изменения в репозитории:

```
bash /opt/gorodchaya/deploy.sh
```

`deploy.sh` делает `git pull` и запускает `update.sh`. Оператор и почта для политики конфиденциальности берутся из `/etc/chaygorod-operator.env`; если файла нет, передайте их один раз: `bash /opt/gorodchaya/deploy.sh "ФИО или ИП" "почта@..."`.

Обновление не трогает секреты, заказы, пользователей, каталог чаёв, диалоги, логи, конфиг CRM.Капитан и сертификаты. В nginx добавляет только подключение `deploy/nginx-tea-routes.conf` и лимит размера для `/admin/`; если nginx не примет конфиг, он возвращается как был.

## Каталог чаёв

Чаи редактируются в админке, вкладка «Продукты»: тексты, фасовки и цены, фото, SEO-заголовок и описание, адрес страницы. Хранятся в бэкенде (`/var/www/chainy-gorod-backend/data/store.json`), не в репозитории.

- Страница чая: `/tea/<адрес>` (файлы `tea/<адрес>.html` печёт генератор). Старый адрес после смены и старые `tea-<id>.html` перенаправляются на новый (301).
- Короткая ссылка для QR: `/t/<номер>`. Номер чая также «ID на сайте» для Битрикса (`110-50`) и номер, которым мастер в чате ссылается на чай.
- После каждой правки бэкенд сам перепекает страницы и `sitemap.xml` и выгружает базу знаний мастера в `tea-consultant/data/teas.json`.
- Цены и остатки из файла остатков: `node /opt/gorodchaya/backend/import-stock.js /opt/gorodchaya/backend/import/ostatki-2026-10-21.json` (от root, после `deploy.sh`; `DRY=1` — только показать). Новые чаи заводятся с минимальным описанием, у уже заведённых меняются только цена и остаток фасовки. Остаток ставится как в файле, поэтому повторно после продаж не запускать.
- Описания из черновика редактора: `node /opt/gorodchaya/backend/import-descriptions.js /opt/gorodchaya/backend/import/opisaniya-2026-10-22.json /opt/gorodchaya/backend/import/ostatki-2026-10-21.json` (после загрузки остатков; `DRY=1` — показать). Сопоставляет по исходному названию из файла остатков, карточки мастера и описания, уже правленные в админке, не трогает (`FORCE=1` — перезаписать). Что нужно сверить по этикетке, видно в админке в карточке («сверить») — на сайт не выводится.
- `backend/seed-master-data.js` — исходные карточки мастера. `seed.js` только добавляет недостающие чаи и не возвращает удалённые; перезаписать всё ими: `FORCE=1 node seed.js`.

## Посуда, «под заказ», продажи в магазине

- Посуда — раздел каталога `teaware` («Посуда» в шапке): цена за штуку (в админке фасовка «0 г»), без вкладок про заварку, мастеру в базу знаний не уходит.
- Нет остатка — купить всё равно можно. Позиция помечается «под заказ» на странице товара, в корзине, в «Моих заказах» и в админке (заказ с жёлтой полосой, у позиции — сколько есть и сколько под заказ).
- Админка → «Заказы» → «+ Продажа в магазине»: товары из каталога, цена по каталогу или своя, оплата, кто продал, телефон. Заказ сразу «Выполнен», остаток списывается. Покупатель с телефоном попадает во вкладку «Пользователи» (с заказами с сайта склеивается по телефону).

## Тесты и откат

- Тестовую продажу в магазине отметьте «тестовая» — потом «Удалить все тестовые» удалит их и вернёт остаток. Любой заказ можно удалить кнопкой «удалить заказ» (списанное вернётся).
- Снимок всех данных (каталог, остатки, заказы, пользователи): `bash /opt/gorodchaya/snapshot.sh before-test`. Делается сам перед каждым `deploy.sh` и перед `import-stock.js`. Хранятся последние 30 в `/var/backups/chaygorod/snapshots`.
- Откат: `bash /opt/gorodchaya/rollback.sh` — список, `rollback.sh last` — к последнему. Всё после снимка пропадёт, но текущее состояние перед откатом само сохраняется снимком `before-rollback`.

## Секреты (в репозитории их нет)

| Файл на сервере | Что внутри |
|---|---|
| `/var/www/tea-consultant/.env` | `OPENAI_API_KEY` и настройки чата (шаблон: `tea-consultant/.env.example`), `CHAYGOROD_API_KEY` |
| `/etc/chainy-gorod-backend.env` | `API_KEY`, `SESSION_SECRET`, `TELEGRAM_BOT_TOKEN` |
| `/var/www/btxcap/config.php` | Почта для заявок и вебхук Битрикс24 (шаблон: `btxcap/config.example.php`) |
| `/etc/nginx/.htpasswd-tea-admin` | Пароль админки |

## В планах

Синхронизация с коробочным Битрикс24: цены и остатки по полю «ID на сайте» вида `110-50` (номер чая, граммовка), заказы как сделки в воронке «Чайный город», статус «В наличии / Под заказ» без ограничений на покупку.
