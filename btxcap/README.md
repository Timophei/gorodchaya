# CRM.Капитан — сайт для своего хостинга

Одна адаптивная страница. Графика извлечена из двух предоставленных макетов без перерисовки. В мобильной версии используется исходная короткая схема. Тексты, навигация, FAQ и форма — HTML. На иллюстрациях остаются растровые подписи исходников. При сильном увеличении они могут терять чёткость.

## Установка

1. Нужен хостинг с PHP 8.1+, расширением cURL, HTTPS и настроенной функцией `mail()`.
2. Папку `public` назначьте корнем сайта. Если хостинг использует `public_html`, скопируйте туда содержимое `public`.
3. Рядом с папкой корня сайта (на один уровень выше, НЕ внутрь неё) разместите `config.php`, скопировав `config.example.php`.
4. Заполните `recipient` — адрес получателя, `from` — отправитель на домене хостинга, `webhook` — входящий вебхук Битрикс24 вида `https://portal.bitrix24.ru/rest/USER/SECRET/`. У пользователя вебхука должно быть право добавлять лиды и доступ к CRM. В портале должны быть включены лиды. Укажите `assigned_by_id`, если нужен ответственный.
5. PHP должен иметь право создать `private-state` рядом с `config.php`; эта папка не должна быть доступна через HTTP.
6. Отправьте тестовую заявку и проверьте одновременно почтовый ящик и лид в CRM. Для почты настройте SPF/DKIM средствами хостинга. Возврат `mail() = true` означает приём сервером, а не гарантированную доставку в ящик.

Без конфигурации обработчик возвращает честную ошибку, а не имитирует отправку. Из локального файла или обычного статического хостинга PHP не заработает.

## Что делает форма

Проверяет имя, телефон/email и согласие, передаёт UTM, отправляет письмо и создаёт лид. Секрет вебхука хранится только на сервере. Есть скрытое поле против простых ботов, ограничение 10 попыток в час на IP и блокировка параллельных повторов одного запроса. Это базовая защита, при заметном спаме добавьте CAPTCHA.

Для совместимости используется документированный `crm.lead.add`. Развитие этого метода остановлено; для дальнейшего развития интеграции Битрикс рекомендует `crm.item.add`. Документация проверена 22.09.2026:
https://apidocs.bitrix24.ru/api-reference/crm/leads/crm-lead-add.html

Если портал требует дополнительные поля, добавьте их в `$fields` в `public/submit.php`.

## Сбои и повторы

Если доставлен хотя бы один канал, посетитель получает подтверждение. При частичном сбое пишется техническое сообщение в журнал ошибок PHP; оператор должен проверить второй канал. Автоматической очереди повторной доставки нет. При тайм-ауте Битрикс сохраняется `pending`: повторно метод создания не вызывается, поскольку первый запрос мог создать лид. Проверяйте заявку по ID из письма / комментария лида перед ручным повтором. Обработчик хранит только хеш контакта и статусы доставки. Периодически удаляйте файлы в private-state старше 30 дней; это задаёт срок защиты от повторов.

## Перед запуском

Проверьте адрес `info@b-integration.ru` в HTML, JS и PHP; замените, если нужен другой. Заполните реальные условия доступа к записям в FAQ. Добавьте утверждённые оператором сведения об обработке данных и ссылку на свою политику/согласие; сейчас есть короткое согласие на обратную связь, это не готовый юридический документ.

## Проверка

Фронтенд проверяется отдельно от реальных интеграций. Почта и CRM не подключены: для сквозной проверки нужны настройки вашего хостинга и вебхук. Никакие реальные письма или лиды при сборке не создавались.

В этой среде проверены синтаксис JavaScript, наличие всех графических файлов и цели навигационных ссылок; графические вырезки просмотрены. Браузерная проверка не выполнена: Chromium отсутствует, загрузка браузера не удалась. PHP-интерпретатор отсутствует, обработчик требует проверки на тестовом PHP-хостинге перед запуском.
